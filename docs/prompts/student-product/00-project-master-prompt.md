# Master Prompt — New Student Product Mockup

Design and code a completely new frontend prototype for an HSK Chinese-learning product. Treat this as a fresh product design exercise, not as an implementation of the repository's existing Admin UI.

## Scope

Build these Student areas with HSK levels **1–9**: Dashboard, HSK Learning Path, Grammar Library, Foundation (Pinyin, tones, radicals, listening and speaking), Workplace Simulator, CBT Exams, Mistake Notebook/SRS, Lego Word Order, Character Writing, and Leaderboard/Streak/Badges.

Do not include Music/Karaoke, PK Arena, or AI Mentor/Tiểu Long anywhere in navigation, routes or UI.

## Prototype rules

- Frontend mockup only. Do not implement backend, database, migrations, authentication, RBAC or real API integrations.
- Use realistic local mock data and local state. Keep mock data in clearly named data files.
- Make interactions demonstrable: tabs, filters, selectors, drawers, modals, progress changes, audio-play placeholders, drag/drop or click ordering, and route navigation should work in the prototype.
- You may create new components, layouts, styles and visual tokens freely. Existing project code is optional inspiration, not a constraint.
- Use the existing frontend framework/build setup if it helps the prototype run, but do not let old project conventions reduce the quality of this new design.

## UI direction

Use the `ui-ux-pro-max` skill freely. Search for a coherent language-learning dashboard direction, then choose the best layout, typography, palette, icon family, motion and accessibility patterns. Unlike production work, you may use the skill's colors and font recommendations directly in this prototype.

The result should feel premium, motivating and game-like without looking childish. Avoid generic SaaS admin dashboards, excessive gradients, excessive glassmorphism and deeply nested cards. Use vector icons rather than emoji for structural controls. Design intentionally for desktop and mobile, not desktop squeezed into mobile.

## Required quality

- Responsive at 1440, 1024, 768 and 375px.
- Light/dark mode if it improves the product; both modes need readable contrast.
- Semantic HTML, keyboard-accessible controls, visible focus, reduced-motion support and accessible labels.
- Include useful Ready, Loading, Empty and Error demo states where relevant.
- Keep shared navigation and visual language consistent across pages.
- Verify the app builds and all prototype routes are navigable.

## Output

Deliver a polished clickable mockup first. Do not spend time designing backend architecture. Clearly label mock data in code so the prototype can later be connected to real APIs.
